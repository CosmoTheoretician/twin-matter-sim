## Plan

**Where the 89 % goes today.** `run_loop_gpu.host()` copies the whole particle set to the host every `log_every` steps (6.4 M particles × 6 floats) and then runs `diagnostics_row`, `lss_structure_row` / `disk_structure_row` (numpy CIC with `np.bincount`, scipy smoothing, numpy FFTs) and `plotting.snapshot` (scatter of all particles + numpy density grids). After the change the particles never leave the device: every sum, every grid, every grid statistic and every density map is computed with torch in float64 on the GPU, and only small things cross the bus — a vector of ~40 diagnostic scalars, a smoothed structure grid (≤ 512² or 128³) for scipy's connected-component labelling, the per-bin arrays of the disk Fourier analysis, 200 × 200 density maps and a fixed 200 000-particle scatter subsample per population.

**Moved to the GPU (new modules, GPU path only):**
- `diagnostics_torch.py` — KE, U (with `phi_ext`), P_abs / P_signed, L (species, abs, signed), dispersions, r_rms, escaped fraction, v_rot, `dE_rel`, `dP_*_rel`, virial, circular-mean centre of mass; same dict keys as `diagnostics_core.diagnostics_row`.
- `grids_torch.py` — CIC density grid (`index_add_`), scipy-exact Gaussian smoothing, Pearson/segregation/void fraction/power spectrum/peak wavelength/persistence, 3-D projections and log images, all on tensors.
- `structure_torch.py` — `lss_structure_row_t` and `disk_structure_row_t` with identical signatures/keys to `structure_stats`; only the smoothed grid (clumps) and tiny per-bin arrays go to the host, where the unchanged `structure_stats` functions (`find_clumps`, `nn_distance`, `bar_strength`, `spiral_strength`, `pitch_angle`, `pattern_speed`) are reused.
- `snapshot_torch.py` — density maps / projections / slices on the device, fixed seeded scatter subsample (`--scatter-subsample`, default 200000 per population, stated in the panel title), same figure layout as `plotting` / `plotting_3d`.
- `timing.py` — a small section timer shared by both loops; breakdown (forces, integration, energy diagnostics, structure statistics, snapshots, other) printed at the end of every run and stored in `summary.json`.
- `run_loop_cpu.py` — the existing CPU time loop moved out of `scenarios.py` unchanged in its numerics, with the timers and the optional final dump added (keeps `scenarios.py` under the size limit).
- `diagtest.py` — the `diagtest` command: one 2-D LSS state, one 3-D LSS state and one 2-D disk+ring state; every diagnostic, structure and snapshot-map quantity computed by the numpy path and the torch path (float64 and float32), differences tabulated with tolerances and a verdict.

**Changed files:** `config.py` (two new fields: `scatter_subsample`, `dump_final`), `run_loop_gpu.py` (rewritten around the device-side diagnostics; no `to_host` except the optional final dump), `scenarios.py` (CPU loop delegated to `run_loop_cpu`, device-aware choice of row/centre functions, timing in summary and printed), `main.py` (two options, `diagtest` subcommand). Untouched: `particles`, `forces_*`, `integrator*`, `gpu_backend`, `gputest`, `initial_conditions`, `external_potentials`, `diagnostics_core`, `structure_stats`, `plotting*`, `sweeps`.

**Numerical identity.** All device reductions, grids and FFTs are done in float64 (the CPU code casts to float64 everywhere, so a float64 GPU run reproduces the CPU numbers to round-off; a float32 run differs only through the float32 particle state). CIC corner recipe, scipy kernel radius/normalisation, power-spectrum binning (`floor(k/dk + 0.5) - 1`), Pearson definition and nan rules are replicated line for line.
